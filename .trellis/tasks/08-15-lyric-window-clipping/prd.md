# 修复沉浸式播放页三行歌词裁剪

## Goal

修复沉浸式播放页（PlayerPage 播放控制页）中部三行歌词窗口的裁剪问题：第三行（当前行下方一行）底部约 9.5px 被视口裁掉，三行应完整可见且当前行居中。

## Background

- 五行滚动歌词窗口（AMLL 式连续滚动）：视口 `player-page__song-meta` 高 79px、`overflow: hidden`；内部窗口 `player-page__meta-window` 固定渲染 5 行（prev2/prev/current/next/next2），通过 `translateY` 偏移让 prev/current/next 三行落在视口内。
- 行几何：每行 13px × 1.5 = 19.5px，行间距 `margin-top: 10px`。
- 当前稳态偏移为 `-19.5px`，导致 next 行视口坐标 69~88.5，超出视口底（79px）9.5px，被裁约半行；同时 prev 行上方多出 10px 空白，三行整体偏下、当前行未居中。
- 正确偏移应为 `-29.5px`（一行 + 一个行距），此时三行 0~19.5 / 29.5~49 / 59~78.5 完整落在视口内。
- 同源问题：切行动画结束后的复位偏移也是 `-19.5px`（`PlayerPage.vue` 脚本内 `onComplete`），需同步修正；动画本身（0 → -29.5px）在偏移修正后几何自然连续。
- 延伸问题：窄高屏单行模式（`max-height: 520px`，隐藏非当前行）下该偏移会把唯一可见的当前行也推出视口，属同一 bug 的延伸，一并修复。

## Requirements

- 稳态下三行歌词（prev/current/next）在 79px 视口内完整可见，当前行基本居中。
- 切行滚动动画视觉连续，无跳动、无瞬移。
- 窄高屏（`max-height: 520px`）单行模式下，当前行完整可见。
- 封面自适应：空间富余（大屏/平板）时封面自动变大铺满可用弹性区，但始终保持正方形（边长 = min(容器宽, 容器高)）；不改动歌词窗口以外的其余布局（进度条、间距等），不引入新的魔法数之外的复杂度；保持现有像素几何风格。

## Acceptance Criteria

- [ ] 正常竖屏：三行歌词完整显示，第三行文字底部不被裁切；当前行视觉居中于歌词视口。
- [ ] 切行时窗口整体上移一行，动画结束无跳变（新当前行落在原当前行位置）。
- [ ] 窄高屏（高度 ≤ 520px，如横屏/车机）：单行歌词完整可见。
- [ ] 封面恒为正方形；大屏空间富余时封面自动变大（不再被 `min(52vw, 280px)` 硬上限限制），窄高屏仍为小封面。
- [ ] 歌曲开头/结尾（prev2、next2 为空占位行）时窗口位置不跳动。
- [ ] `npm run type-check`（或项目等价检查）通过，无新增 lint 错误。

## Notes

- 根因定位已完成，修复点明确：CSS `&__meta-window` 初始偏移与 JS `onComplete` 复位偏移两处 `-19.5px` → `-29.5px`（实现为 `--meta-window-offset` CSS 变量 + 清内联回落），外加窄高屏 media query 微调（视口 19.5px、偏移 -10px、跳过动画）。
- 封面改动（用户验证后提出）：`width: min(52vw, 280px)` → auto + `aspect-ratio: 1` + max 约束，跟随弹性区尺寸保持正方形。
- 轻量任务，PRD-only，无需 design.md / implement.md。
