# PRD：修复英文歌翻译行错位一行（译文配对到下一句）

## 背景现象

用户反馈：英文歌的翻译行整体后移一行——第一条歌词的翻译显示在第二条歌词上，最后一条翻译落单，结尾多出一个孤立中文行。

## 已复现的根因（离线脚本 + 真实平台数据验证）

`src/features/lyrics/mergeTranslation.ts` 的 `mergeDuplicateTimestampTranslations`
按「**相邻两行 startTime 差 ≤ 50ms**」配对双语主行。当主词双语 LRC 中
**译文行的时间戳打在下一句原文上**（而非与自己的原文同时间戳）时，相邻配对把
译文配给下一句原文：

```text
[00:10.00]Hello world
[00:15.00]你好世界   ← 第一句的译文，时间戳却等于第二句
[00:15.00]Second line
[00:20.00]第二行
[00:20.00]Third line
[00:25.00]第三行     ← 落单 → 结尾多一个中文行
```

结果：所有译文整体后移一行，最后一条译文单独成行。与用户描述完全一致。

## 需求

1. 修复上述错位：整首歌呈现「原文/译文交替」结构时，译文必须配回**它前面的**原文行（按文件顺序配对），不允许整体后移。
2. 不回归现有正确场景（离线脚本已验证过的）：
   - 网易 lrc 主词 + tlyric 时间戳对齐（挂载正确）
   - 主词双语同时间戳成对（合并非 Han 主行 + Han 译文，顺序不限）
   - tlyric 已挂载的行不再参与双行合并
3. 不吞掉「同时间的两句独立歌词」（非翻译对不合并）的既有保护。

## 附加发现（本次顺带确认，允许纳入或另开任务）

网易 **yrc 主词 + tlyric** 场景：yrc 行时间与 tlyric 普遍偏差 300~700ms，超出
`TRANSLATION_MATCH_TOLERANCE_MS = 80` 容差，翻译基本挂不上（表现是「逐字歌词没有翻译」，
与本次错位是不同症状）。修复方案若顺带能覆盖（如序列感知匹配）则一并处理，否则记录待办。

## 验收标准

- [ ] 复现脚本中「译文时间戳打在下一句」的用例：每条译文挂回前一条原文行，结尾无孤立中文行，总行数 = 原文行数。
- [ ] 现有正确场景（tlyric 对齐挂载、同时间戳双语合并、已有翻译不覆盖）回归通过。
- [ ] 非翻译对（同时间戳的两句独立歌词，脚本相同）仍不被合并。
- [ ] yrc+tlyric 场景处理策略明确：要么修复（翻译可挂上），要么明确说明为何不在本次范围。
- [ ] `pnpm lint` / `vue-tsc` 构建通过。

## 非目标

- 不改 AMLL 库本身，不改 provider 抓取逻辑（除非验收需要最小辅助）。
- 不处理音译（romanLyric）行。
