# 改为推屏式 Salt 侧栏导航

## 目标

把现有移动端覆盖式导航抽屉改为 Salt Player 风格的推屏式侧栏：侧栏与主页面处于同一布局层级，打开时侧栏从左侧显露，主页面同步向右移动；关闭时两者同步复位。

## 背景与已确认事实

- 当前 `src/views/TabsPage.vue` 使用固定定位的抽屉与全屏遮罩覆盖主页面，主页面本身不移动，这与目标效果不符。
- 当前导航已经支持汉堡按钮、全页右滑打开、抽屉内左滑关闭、Escape/菜单选择关闭、四入口路由高亮、详情页父入口高亮和焦点恢复。
- MuMu WebView 110 横向移动后会提前发送 `pointercancel`，现有 Touch Events 手势状态机已经通过运行态验证，应继续保留该兼容方案。
- 平板在 `>=768px` 时使用固定 260px 左侧导航，不属于本次移动端推屏动画改造范围。

## 需求

- 移动端侧栏与主页面必须位于同一个布局/动画轨道中，不再把侧栏作为覆盖在主页面上方的独立固定抽屉。
- 移动端侧栏展开宽度固定为当前屏幕宽度的 50%，主页面保持原宽度，不进行缩放或内容重排。
- 打开导航时，侧栏从左侧显露，主页面按照同一手势进度同步向右平移 50vw，右侧自然裁出视口；关闭时同步向左复位。
- 拖动过程中侧栏和主页面必须跟手，不得只在松手后跳转到最终位置。
- 保留汉堡按钮、页面任意位置水平右滑打开、侧栏区域或已推开的主页面水平左滑关闭、Escape、菜单选择关闭和焦点恢复。
- 保留歌曲、音乐库、音源、设置四个入口、现有路由、业务逻辑和详情页父入口高亮。
- 保留平板 260px 固定左侧导航，不应用移动端推屏位移。
- 继续使用 motion-v 处理结构性收敛动画，继续使用 Touch Events 规避 WebView 110 的 `pointercancel` 行为，不新增依赖。
- 保持 MiniPlayer、全局弹层、播放器和队列层级及底部安全区契约，不恢复底部 Tabbar。

## 验收标准

- [ ] 移动端关闭状态下，主页面占满视口，侧栏位于视口左侧不可见区域。
- [ ] 点击汉堡或全页水平右滑时，侧栏和主页面按同一进度联动，主页面被整体向右推开。
- [ ] 打开状态下，侧栏恰好占屏幕宽度的 50%，主页面保持原宽并向右位移 50vw，右侧自然裁切，不缩放、不重排，也不被侧栏覆盖。
- [ ] 侧栏区域或已推开的主页面水平左滑能够跟手关闭；纵向滚动不会误触发导航。
- [ ] Escape、菜单选择及适用的非手势关闭入口均可关闭侧栏，且焦点恢复正确。
- [ ] 四个导航入口、路由高亮和详情页父入口高亮保持正确。
- [ ] 平板固定侧栏、MiniPlayer、播放器、队列、Popup/Dialog/Sheet/Toast 的布局和交互不回归。
- [ ] `npm run build`、`npm run lint`、`git diff --check`、Capacitor Android 同步与 Debug 构建通过。
- [ ] MuMu WebView 110 上验证汉堡打开、右滑打开、左滑关闭、纵滑不误触、菜单导航和无 JS/Vue/崩溃错误。

## 范围外

- 不改变导航入口、路由路径、页面业务逻辑或数据流。
- 不删除 `MTabbar` / `MTabbarLink` 公共组件。
- 不改变平板固定侧栏宽度或重新设计平板布局。
- 不引入 SaltUI、Compose、Kotlin 或新的 UI/手势依赖。
