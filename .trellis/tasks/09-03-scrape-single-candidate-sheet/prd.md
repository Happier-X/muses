# 单曲即时刮削候选浮层

## Goal

单曲点“刮削”即弹候选浮层，当场选候选直接写回，不走队列；对齐专业软件的逐字段对比与封面/歌词预览。

## 背景

- 现有刮削仅走“入队→刮削页→全部开始→预览→写回”队列四态，单曲即时操作绕路
- 用户期望像 Picard/MusicTag 的即时刮削：点一首即搜候选、对比原/新、选一键写回

## Requirements

### R1 入口与封面可见（P0）
- 歌曲 ⋮ 菜单“刮削”即时入口与“加入待刮削”队列入口并存，点单曲直接拉起浮层不入队
- 封面链路修复：`effectiveCoverUri` 已落库但仍不可见，需保证刮后 `coverUri/metaCover` 优先展示且 `AudioTagReader` 缓存失效，列表/迷你条/沉浸页立即可见（回归 09-03 封面任务）

### R2 候选浮层（P0）— 融合 A/B/C
- 三态：搜索中（转圈）→ 候选列表 → 无命中/限流重试
- 每候选卡：**原 vs 新逐字段对比**（标题/歌手/专辑/歌词摘要分行，**差异高亮**，未变灰显），**封面大图缩略**（多候选可左右滑，首版单候选缩略+点放大），**置信度徽标**，**单选候选**
- **逐字段勾选**（A 形态）：标题/歌手/专辑/封面/歌词各一个勾，默认全勾可单关，仅勾选字段参与写回；与编辑互斥时以勾选为准
- **现场编辑**：卡内“编辑”展开三字段+歌词多行编辑，编辑后即为该字段拟写回值且自动勾选该字段
- 顶部 **批量全选/全不选字段**（B 形态），与队列页批量一致

### R3 写回（P0）
- 底部“应用”仅当选中一候选且至少一字段勾选时可用，组装 `ScrapeChanges` 时仅含勾选字段（未勾字段传 null 不落库），调 `WritebackOrchestrator` 单条写回，成功 Toast“已更新”并关闭浮层，Room Flow 立即刷新

### R4 队列保留（P1）
- 保留队列批量四态路径（队列→匹配→预览→结果），与单曲浮层互不阻塞；限流文案一致

### R5 回归（P1）
- 未勾选字段不污染原值，未命中封面/歌词保持原值；WebDAV/本地均覆盖

## Constraints

- 仅新增 `feature:scrape/SingleScrapeSheet` 与 `SingleScrapeViewModel` 状态机，复用 `TextMetaMatcher/CoverMatcher/EditCloudMetaSearch` 能力
- 浮层不做多候选源切换，首版仅展示最优候选（置信度最高）+ 封面，多候选左右滑为后续迭代

## Acceptance Criteria

- [ ] **AC1 入口**：歌曲页任一歌曲 ⋮ 点“刮削”立即弹出浮层，标题为“刮削 - 歌名”
- [ ] **AC2 对比**：浮层可见“原：… / 新：… ”逐字段对比，变更字段高亮，封面缩略可点放大
- [ ] **AC3 编辑写回**：候选内改标题后点“应用”，库内该曲标题为编辑后值，切到播放页立即可见
- [ ] **AC4 无命中**：无候选时显示“暂无匹配”与重试按钮，限流时显示“触发限流，稍后重试”
