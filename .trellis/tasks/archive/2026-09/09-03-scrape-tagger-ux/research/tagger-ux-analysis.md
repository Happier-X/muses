# Ericwyn/tagger 操作逻辑分析

来源：https://github.com/Ericwyn/tagger （README + 架构文档截图），抓取日期 2026-09-03。

## 项目定位

Go + Web 前端的本地音乐标签整理工具（自部署 Web 工作台），核心页面是一个**一体化工作台**：
左侧曲库/目录树（按文件夹浏览 + 按状态过滤，如"未刮削"），顶部搜索框，中间曲目列表，右侧 **Inspector**（选中曲目的元数据查看与编辑面板）。

## 核心操作流（用户想要的体验）

四段式：**浏览 → 查询 → 审核 → 写入**。

### 1. 浏览（就近触发）
- 在曲目列表里直接看到每首歌的刮削状态；可按目录、状态（未刮削/已刮削）过滤。
- 选中一首歌立即在 Inspector 里看到本地现有标签，**不离开当前页面**。

### 2. 查询（多源并行、原始候选全保留）
- 对选中曲目发起查询时，**全部启用数据源并行查询**（MusicBrainz、LRCLIB、Apple/iTunes、网易云、酷我、酷狗、LrcApi 等）。
- **智能选择 + 原始候选保留**：字段级智能选择自动给出"推荐采用"的候选，但所有源的原始候选全部保留，用户可以随时切换。
- 支持**单曲重新匹配**：对不满意的结果修改关键词重搜。

### 3. 审核（本地值 vs 候选值逐字段对比）
- 逐字段显示：本地值 → 候选值，字段真实来源（哪个数据源提供）。
- 逐字段选择：全选/取消，每个字段独立决定是否采用。
- **候选切换**：同一字段可在多个候选间切换。
- 歌词/封面详情预览（封面可选写入尺寸）。
- **连续审核**：审完一首接一首，不需来回跳页。

### 4. 写入（任务中心 + 历史）
- 确认后创建写入任务，任务中心管理（扫描/抓取/写入任务持久化、进度、取消、失败重试）。
- 历史记录保留字段 diff 与快照，可恢复。

## 与 muses 现状的关键差异

| Tagger 逻辑 | muses 现状 | 差距 |
|---|---|---|
| 列表就地选中 → 审核，不跳页 | 单曲：⋮ 入队 → 切刮削 Tab（5 步）；即时浮层已成孤儿（`SongsPage.kt:108` 无调用点） | 入口绕路 |
| 多源并行查询，原始候选全保留、可切换 | `TextMetaMatcher` 首个命中即返回，预览只见单一候选，黑盒 | **无候选切换（核心差距）** |
| 修改关键词单曲重搜 | 无重搜能力（`EditCloudMetaSearch` 引擎支持 8 候选但 UI 只取首个） | 无重搜 |
| 本地值 vs 候选值逐字段对比 + 来源 | 预览已有逐字段 Checkbox + 原值→新值 + 置信度角标（91b7c13c 刚做） | 基础已有 |
| 未命中可见、可重试 | 队列匹配失败的歌曲静默消失 | 不可见 |
| 连续审核 | 预览态列表逐首滚动确认 | 弱 |
| 歌词在主流程内 | 主流程 `matchedLyrics` 恒为 null，歌词只能去播放页编辑弹层 | 缺席 |

## 结论

muses 已有的资产与 Tagger 的差距集中在三件事：
1. **引擎层**：匹配链从"首个命中即返回"改为"多源候选聚合 + 推荐排序"（智能选择）。
2. **单曲审核工作台**：一个全屏审核界面 = 多候选切换 + 逐字段对比勾选 + 改关键词重搜 + 封面/歌词预览 + 写回；从歌曲列表就近触发。
3. **批量流接入同一审核形态**：批量匹配后逐首连续审核；未命中列出、可重试；歌词进主流程。
