# 加入待刮削成功失败提示

## Goal

点击“加入待刮削”（歌曲 ⋮ 菜单 / 多选条）后给予明确的成功/已在队列/异常轻提示，避免静默无反馈。

## 背景

- 当前 `ScrapeQueueAccessViewModel.enqueue` 为 fire-and-forget，无 UI 回显
- 用户点击后无感知是否成功，需到刮削页队列手动确认

## Requirements

### R1 入队成功提示（P0）
- 单首：`已加入待刮削队列`
- 批量 N>1：`已加入 N 首到待刮削队列`
- 已在队列中的幂等场景：若新增 0 首则提示 `已在待刮削队列中`（或 `已加入/已在队列` 合并文案，二选一保持简洁）

### R2 异常静默不打扰（P1）
- 队列读写异常极罕见，失败时不弹错误打扰，控制台留痕即可（与现有静默风格一致）

### R3 触发入口全覆盖（P0）
- 歌曲页单首 ⋮ 菜单与多选批量两处入口均需提示
- 提示在歌曲页本地展示，不依赖跳转刮削页

## Constraints

- 仅改 `feature:scrape` 与 `feature:library` 展示层，不改 `ScrapeQueueStore` 入队幂等语义
- 复用 `SnackbarHost`/`Toast` 二选一，文案中文，遵循现有设计令牌
- 不引入全局事件总线，仅在歌曲页局部回显

## Acceptance Criteria

- [ ] **AC1 单首**：歌曲 ⋮ 菜单点“加入待刮削”后 300ms 内出现 Snackbar/Toast “已加入待刮削队列”
- [ ] **AC2 批量**：多选 3 首点“加入待刮削”后提示“已加入 3 首到待刮削队列”
- [ ] **AC3 幂等**：对已在队列的单首再次点入队，提示“已在待刮削队列中”（或仍为成功文案，二选一验收通过）
- [ ] **AC4 回归**：未点入队时无提示，刮削页队列计数仍正确
