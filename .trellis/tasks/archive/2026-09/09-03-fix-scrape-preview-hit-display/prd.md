# 修复刮削预览命中但新值为-的展示混淆

## Goal

消除“共 N 首命中却新值为 — · — 且封面空”的误导，按文本/封面维度分别展示命中结果与空值原因。

## 背景

- 当前 `startMatching` 以 `hit != null || coverUrl != null` 计数命中，新行仅取 `hit.title/artist/album`，封面单列 `coverUrl`
- 文本仅命中时封面空、封面仅命中时文本全“—”，均会让用户误以为命中无数据

## Requirements

### R1 命中计数分维度（P0）
- 顶部由“共 N 首命中”改为“文本命中 N · 封面命中 M · 去重共 K”，M/K 均可推导，至少展示文本与封面各自计数

### R2 新值空值文案（P0）
- 标题/歌手/专辑为 `null/空串` 时展示 `—` 保持不变，但当三字段全 `—` 时行尾补充 `（无文本变更）` 灰字标签，避免空白歧义
- 封面 `null` 时缩略区展示 `无封面` 占位已存在，补充小字原因：`未命中封面` 或 `命中仅文本` 的区分（文本仅命中时显示“仅文本命中”）

### R3 行内维度标签（P1）
- 每行新值右侧增加维度徽标：`文本` / `封面` / `文本·封面`，复用置信度徽标样式，便于一眼区分

## Constraints

- 仅改 `feature:scrape` 预览 UI，不改匹配/写回逻辑与阈值
- 复用 `Salt*` 与现有颜色，布局不溢出窄屏

## Acceptance Criteria

- [ ] **AC1 分计数**：文本仅命中 2 首、封面仅命中 1 首时，顶部显示如“文本命中 2 · 封面命中 1 · 共 3”
- [ ] **AC2 空文案**：文本全空行显示“新：— · —（无文本变更）”而非裸“— · —”
- [ ] **AC3 维度徽标**：文本仅命中行显示“文本”徽标，封面仅命中行显示“封面”，双命中显示“文本·封面”
- [ ] **AC4 回归**：双命中且三字段齐全时仍正常显示标题/歌手/专辑与封面缩略，无文案遮挡
