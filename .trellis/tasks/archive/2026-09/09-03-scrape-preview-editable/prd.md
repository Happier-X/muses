# 刮削预览可见匹配结果并支持编辑

## Goal

刮削预览页展示匹配到的完整元信息（标题/歌手/专辑/封面及置信度），并支持在写回前现场编辑后再落库，保证"所见可改、所改即写回"。

## 背景

- 当前预览仅展示一行`匹配标题·歌手`和`当前艺术家[置信度]`，封面仅存 URL 未可视，无法直观对比前后差异
- 用户希望在预览中直接修改刮到的标题/歌手/专辑（及封面选择），再执行写回，避免"先写回再二次编辑"的绕路

## Requirements

### R1 完整可见（P0）
- 预览每行展示`原值 → 新值`对比：标题、歌手、专辑三字段各自显示`当前值 / 匹配值`（匹配为空时显示"—"或保留原值占位）
- 置信度（HIGH/MEDIUM/LOW）与封面缩略图可视展示，封面无命中时显示占位
- 三字段对比在窄屏下可读（两行或分段布局，不溢出）

### R2 现场可编辑（P0）
- 预览每行提供编辑入口，允许修改`标题/歌手/专辑`的拟写回值，初始值填充为匹配结果（为空则回退原值）
- 编辑态为覆层形态（BottomSheet/Dialog），不破坏预览列表勾选与批量操作；编辑完成后回写到该行的待写回值
- 封面通过候选缩略选择或保留原封面（本任务不做粘贴 URL 输入，仅做可视 + 清除/保留）
- 仅对勾选项生效：未勾选行编辑不参与写回；编辑不自动勾选（由用户显式勾选控制）

### R3 写回一致（P0）
- 确认写回时使用编辑后的值组装 `ScrapeChanges`（title/artist/album/coverRemoteUrl），未改字段按原匹配语义落库
- 空串语义与写回层一致：标题空白视为不改（避免空标题入库），歌手/专辑空串视为不改（与 `EditMeta` 取空回退语义一致）
- 单首重试与批量重试路径保持与编辑后值无关（重试是重新匹配，需重新进入预览编辑）

### R4 交互与状态（P1）
- 编辑入口仅在 Preview 态可见，Writing/Result/Matching/Queue 态不可见
- 编辑弹层支持取消（丢弃本次改动）与确认（回填行内）
- 列表支持滚动与多选共存，编辑弹层不影响其它行勾选态

## Constraints

- 复用现有 `Salt*` 组件与 `EditMeta` 的字段校验语义，不引入新的网络请求
- 仅改动 `feature:scrape` 与 `core:scrape` 预览模型/视图层，不改动 `WritebackOrchestrator` 五步流程
- 写回安全红线保持：预览默认全不选，写回按钮仅当 `any{checked}` 可用

## Acceptance Criteria

- [ ] **AC1 可见**：刮削命中 1 首以上时，预览每行可同时看到原标题/歌手/专辑与匹配标题/歌手/专辑及置信度，封面命中时显示缩略图
- [ ] **AC2 编辑**：点击某行编辑入口，弹层内三字段可改，确认后该行展示的拟写回值同步更新，再点编辑仍为上次改后值
- [ ] **AC3 写回**：勾选并编辑标题后点"写回选中"，库内该歌曲标题为编辑后值（而非原始匹配值）；未勾选行不写回
- [ ] **AC4 取消**：编辑弹层中改标题后点取消，该行拟写回值保持改前不变
- [ ] **AC5 回归**：未编辑时写回行为与现有一致；多选/全选/单首重试/限流重试无回归
