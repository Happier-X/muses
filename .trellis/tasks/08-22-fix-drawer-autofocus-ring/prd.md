# PRD：抽屉首次打开菜单项出现蓝色焦点框

## 背景

用户反馈：首次打开侧边栏时，菜单项有蓝色框。

根因（已实测定位）：
- 抽屉打开时代码程序化聚焦第一个菜单项（`drawerLinkRefs.value[0]?.$el?.focus()`，TabsPage.vue 3 处：227/368/407 行附近），服务于键盘导航与读屏焦点管理。
- 菜单项有无障碍焦点样式 `:focus-visible { outline: 2px solid var(--m-primary) }`，主题色为蓝色 `#0470e6`。
- 首次打开时无前置交互，MuMu WebView 对程序化 focus 判定了 `:focus-visible` → 显示蓝色描边框。

约束：规范明令「禁止移除抽屉链接的 focus() 焦点陷阱逻辑」（无障碍回退会失效），focus 行为必须保留。

## 需求

1. 程序化聚焦首个菜单项时不显示焦点描边（触摸场景下任何菜单项都不应出现蓝框）。
2. 真实键盘 Tab 导航的焦点指示保留（`:focus-visible` 对键盘场景照常生效）。
3. 抽屉关闭再打开、重复打开均不出现蓝框；焦点管理逻辑（Esc 关闭、焦点回触发按钮等）行为不变。

## 实现要点

- 程序化 focus 前给元素加标记类（如 `tabs-layout__nav-link--auto-focus`），CSS 以 `:focus-visible:not(--auto-focus)` 排除描边；元素 blur 时移除标记类（真实 Tab 移动焦点后自然恢复指示）。
- 封装统一的 focus 辅助函数替换 3 处裸调用。

## 验收标准

1. MuMu 实测：首次及重复打开抽屉，菜单项无蓝色框。
2. 键盘 Tab 在抽屉内移动时焦点环正常显示（可用 CDP 模拟验证或代码审查确认）。
3. lint / vue-tsc / 单测通过。
