# v0.6.4

## 新增

### 首页（新的启动落地页）

- 新增「首页」并作为**启动默认页**：顶部搜索框 + 「排行榜」+「猜你喜欢」；导航侧轨/抽屉首位（原曲库/专辑/艺术家/歌单/设置保持不动）
- 搜索框回车即跳在线搜索页**并自动搜索**（复用现有搜索页，不重复造一套搜索 UI/状态机）

### 排行榜（QQ音乐 / 酷狗 / 网易云，均免登录）

- `:core:search` 新增榜单能力：`OnlineChartProvider`（榜单列表 + 榜单歌曲）与 `OnlineChartService` 聚合（单平台失败不阻断其它平台）
- 三平台实测可用：QQ 30 个榜、酷狗 56 个榜、网易 63 个榜；榜单歌曲产出与搜索结果**同构**（含 `musicInfoJson`），走同一条播放链路（脚本校验 → 会话登记 → 播放端口）
- 酷我榜单接口需要 CSRF Token（移动端与 wapi 两路实测均拒绝），暂未接入；搜索侧仍保留酷我

### 猜你喜欢（AI 读曲库推荐）

- 新增 `:core:ai`：曲库画像（高频歌手/专辑 + 来源分布 + 抽样曲目）→ LLM（OpenAI 兼容）→ 歌名/歌手 → 各平台**精确匹配**
- 预置服务商下拉：DeepSeek / Kimi / 智谱 GLM / 通义千问 / 自定义（OpenAI 兼容地址），模型可用默认或自填
- **API Key 加密存储**（安卓 Keystore / 桌面 DPAPI，经 `CredentialsRepository`），且**不回显**：已保存时输入框只提示「已保存（留空不修改）」
- 隐私口径：只外发**聚合统计 + 抽样曲目**，不含文件路径、来源地址、凭据；外发内容的唯一定义点在 `LibraryProfile.toPromptText()`
- 对 LLM 幻觉的处置：匹配不到平台的建议**直接丢弃**，UI 如实显示「AI 推荐 N 首，匹配到 M 首」，不掩盖失真
- 设置页新增「AI 推荐」分组：开关、服务商、地址、模型、Key、保存与**连接测试**（测试前先落盘，避免测到上一轮配置）

### 在线音源：封面与歌词展示链路

在线曲目（不入库）此前播放页没有封面、没有歌词，标题/艺术家也空白（只认 Room 实体）；现将洛雪脚本的 `pic` / `lyric` 动作经端口接入既有封面·歌词渲染链路：

- `:core:common` 新增 `OnlineTrackMetadataResolver` 端口 + `OnlineTrackLyrics` 四字段模型（与 `OnlineTrackResolver` 分开：直链属播放链路，封面/歌词属展示链路，失败语义不同）；`OnlineTrackSession` 由 Mutex + Map 改 StateFlow，`remember` 改非 suspend 让播放链路在 `setMediaItems` 之前同步登记，并新增 `observe()` 把「迟到登记」推给订阅方，消除「先观察、后登记」导致封面/歌词永久缺失的竞态
- `:core:lxsdk` 新增 `LxScriptRepository.resolveLyric` / `resolveCover`（按 platform 路由 + 声明校验 + 逐脚本尝试，与 `resolveMusicUrl` 同口径）与 `LxOnlineMetadataResolver`（失败静默折算 null，协程取消原样抛出）——`getLyric` / `getPic` 此前已实现但零调用，现接入
- 新增 `LxLyricParser`：四字段 → `LyricsDocument`（逐字行标 `WordSynchronized` 走 AMLL 逐字渲染，翻译/罗马音按 1.5s 容差对齐）；逐字时间基准容错（酷我/酷狗系为绝对毫秒、咪咕系为相对行首，按「首字是否显著早于行头」判定并平移；时间回退时钳到前字结束）；第三方脚本直接返回平台原始歌词（KRC / QRC / YRC / TTML）时按 timing 括号形态分流兜底
- 新增 `CachedOnlineTrackMetadataResolver`（有界 LRU 16，只缓存成功结果）：播放页与迷你条共享 Koin 单例后，同一首在线曲目只真正拉一次脚本
- 展示层：`PlayerViewModel` 当前曲元数据改为「曲库实体 ∪ 在线会话条目」组合流，新增 `nowPlayingMeta`（标题/艺术家先发布、不等网络）；`PlayerScreen` 标题与 `hasSong` 改用它；迷你条标题·艺术家·封面与迷你条歌词模式一并接入；封面优先级 **脚本 pic → 搜索结果远程封面 → 播放器实时 metadata**
- 安卓通知/锁屏/系统卡片封面：在线曲目把搜索结果自带的远程封面直接挂到 `MediaMetadata.artworkUri`（零额外请求；不在入队时预解析脚本 pic，避免出声迟到数十秒）
- 未做：桌面 Windows SMTC 封面（需 WinRT 静态工厂激活 + 缩略图流互操作）

### 桌面：随包内置 VLC 运行时（免装 VLC 桌面版）

- **内置 VLC 运行时构建链路**：`scripts/prepare-vlc-runtime.ps1`（定位源 → 解压 → 裁剪）+ `scripts/vlc-trim-keep.txt`（纯音频最小集白名单：保留 libvlc/libvlccore、音频输出/滤波/混音、常用解码器与 demux，裁掉 gui / video / d3d / 字幕渲染等），Gradle 任务 `prepareVlcRuntime` 在打包前产出 `appResources/windows/vlc`（182MB → 约 40MB）
- **VLC 原生库发现优先级**（`JvmPlayerPort.resolveVlcDir()`）：显式配置 `MUSES_VLC_DIR` / `muses.vlc.dir` → 随包内置 `app/resources/vlc` → 仓库便携版（开发态）→ 系统已装 VLC 桌面版 → 交给 VLCJ 自行发现；配套单测覆盖候选顺序与「目录存在但缺 `libvlc.dll` 需跳过」的口径

## 变更

### 窄屏导航：悬浮底栏 → 推屏式侧滑抽屉

- 窄屏（<768dp）不再用底部悬浮导航栏，改为**侧滑抽屉菜单**（顶栏汉堡按钮打开、水平拖拽开合、选中项高亮、点击后自动收起）
- **零新增依赖的自研实现**（不引 material3）：miuix 0.9.4-rc01 未提供 Drawer 组件（已核对全部模块，仅有 Rail/NavigationBar/BottomSheet），而 material3 的 `ModalNavigationDrawer` 只有「覆盖 + 遮罩」一种形态、**做不出推屏**；推屏真正需要的只有「两条同步位移 + 一个点击层」，用 Compose foundation 的 `Animatable` + `graphicsLayer` + `detectTapGestures` 即可
- **推屏式（非覆盖）**：抽屉滑出时**内容整体右移**（椒盐/Salt Player 口径，与 SaltUI 示例的 `Row { SideBar(220dp); content }` 同源），因此无遮罩、抽屉在内容下层、两者同为 surface 同色，靠位移本身拉层次；另留透明点击层做「点内容区收起」并防误触
- 视觉按椒盐口径：**直角、无阴影、与页面同色**，宽度 **220dp**（SaltUI 的 `SideBar` 即 `fillMaxHeight().width(220.dp)`）
- **迷你条同步位移**：推屏时底部迷你条必须跟着右移，否则会出现「内容被推开、底部条不动」的穿帮；但迷你条在 Scaffold 的 `bottomBar` 槽、内容在 `content` 槽——两者是兄弟节点，CompositionLocal 传不过去，故把抽屉状态（`PhoneDrawerState`）提到壳层 `MusesApp`，用同一份 progress 驱动两处
- **手势：水平拖拽跟手开合**（右滑开、左滑关），松手按位置阈值（>50%）结算；松手先 `snapTo` 承接拖拽位置再动画，避免回跳
  - 不做「左边缘专属手势」：安卓 10+ 左右边缘是**系统返回手势**区，应用抢不过且会把返回手势废掉；改用**全局水平拖拽**（与系统无冲突）
  - 全局拖拽**不会抢**内容区横向滚动：Compose 手势在 Main pass 中从子到父分发，内层 `horizontalScroll`（首页平台/榜单胶囊）先消费事件——MuMu 实测：胶囊正常横滑、抽屉不误开
- 入口不止手势：顶栏汉堡按钮打开、点内容区/点菜单项收起、安卓返回键优先关抽屉
- 连带修正：`PhoneBottomChromePadding` 184dp → 96dp（窄屏不再有底栏，否则列表底部会多出约 88dp 空白）；`MusesApp` 移除底栏与「迷你条与底栏等宽对齐」的动态边距计算
- 宽屏（≥768dp）保持官方 `NavigationRail` 侧轨不变；刮削/音源入口仍在 设置 → 工具（两端一致）

## 修复（Windows 桌面端）

- **打包版必现「未找到 VLC 原生库」**：安装包既不携带 VLC，运行时也只认 `MUSES_VLC_DIR` 与仓库开发期便携目录（`spike-vlcj/...`）——两者在发行版机器上都不存在，于是只要该机器没装 VLC 桌面版，播放就必然报错。现在安装包**随包内置裁剪后的 VLC 运行时**（`app/resources/vlc`，约 40MB），装完即可播放，无需再装 VLC
- **原生库链接失败直接崩到 UI**：VLCJ 加载不到 `libvlc` 时抛的是 `UnsatisfiedLinkError` / `NoClassDefFoundError`（`Error` 系），原先的 `catch (Exception)` 接不住，友好文案形同虚设。已补 `catch (LinkageError)`，缺失/损坏统一收敛为可操作提示
- **装了 VLC 桌面版也可能找不到**：VLC 安装目录默认不进 `PATH`，此前只靠 VLCJ 自带发现。现补充注册表 `Software\VideoLAN\VLC` 的 `InstallDir`、`%ProgramFiles%` / `%ProgramFiles(x86)%` / `%LOCALAPPDATA%\Programs` 下的 `VideoLAN\VLC` 约定路径，以及 `PATH` 上的 `vlc.exe` 目录
- **在线音源失败提示被吞成通用文案**：`ONLINE_RESOLVER_MISSING` / `ONLINE_RESOLVE_FAILED` 未登记进 `SAFE_PLAYBACK_ERRORS`，经 `onSongFailed → safeCopy` 被静默换成「播放失败，请稍后重试。」，用户拿不到「去检查音源脚本」的指引（`ONLINE_RESOLVER_MISSING` 当时还是零引用死常量，已接入解析器缺失分支）

## 说明

- 「猜你喜欢」需先在 设置 → AI 推荐 配置服务商与 API Key；未配置时首页展示引导卡片而不是空白
- 点榜单/推荐播放需已导入对应平台的洛雪音源脚本（未导入会提示去导入，与在线搜索页同口径）
- 发版 CI 新增 VLC 官方包下载与 SHA256 校验步骤（`vlc-3.0.21-win64.zip`），并校验安装包内确实产出内置运行时；本地构建无 VLC 源时仅告警不失败。随包分发 VLC 的许可与源码获取方式见 `docs/THIRD_PARTY.md`
- 窄屏抽屉里目前是 6 项（首页/曲库/专辑/艺术家/歌单/设置），刮削与音源仍在 设置 → 工具
