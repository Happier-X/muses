# v0.6.5

## 修复

### 窄屏侧边栏：拖拽手感

- **"要滑很远才能打开"**：三个原因叠加
  1. 拖拽回调里读的是**外部状态**（要等重组才更新），连续拖拽事件反复读到上一帧旧值——实测滑 150px 只累积 42px（**丢 72%**）。现改为**本地累积位移**，外部进度只用于上报；
  2. 位置阈值 0.5 太高，必须把抽屉拖过一半（约 330px）才开。降到 **0.25**；
  3. 没有速度判定，短促快滑无效。现**速度优先**：>300px/s 时不论距离按方向结算（真机一划即开），慢速才看位置阈值

### 窄屏侧边栏：底部迷你条位置

- 推屏时迷你条跟着内容一起右移，看起来像"属于当前页面"。现改为**固定在底部**——它是 Scaffold 的 `bottomBar` 槽、全局常驻的播放控件，推屏只作用于内容与侧栏

### 底部迷你条被系统手势小白条压住

- `MusesApp` 的 Scaffold 用 `contentWindowInsets = WindowInsets(0,0,0,0)` 关掉了自动 inset；原先底部有 miuix `FloatingNavigationBar` 时它自己会吃 inset，底栏改成侧滑抽屉后底部只剩自绘迷你条，没人处理 inset → 迷你条被手势小白条（导航条）压住
- 新增 `bottomSystemBarInset()`（expect/actual）：安卓取 `WindowInsets.navigationBars` 底部 inset（手势约 24dp / 三键约 48dp），桌面恒为 0
- 两处消费：**迷你条自身底部留白**；以及**列表末项避让**（`LocalBottomChromePadding` 加上该 inset，否则最后一项会被迷你条与手势区一起遮住）

### 侧边栏未避开顶部状态栏

- 侧栏是自绘的（内容区各页面的 `MusesTopBar` 自带 statusBars inset，侧栏没有），顶部内容会被状态栏压住
- 新增 `topSystemBarInset()`（expect/actual，安卓取 `WindowInsets.statusBars`，桌面 0），侧栏内容下移该高度；背景仍铺满到屏幕顶部（padding 放在 `background` 之后），状态栏区域保持侧栏同色

### 首页歌曲列表没有封面

- **榜单歌曲**：`SongListItem` 的 `SongItem` 数据类原本没有封面字段，首页榜单 20 首全是纯文字；现给 `SongItem` 加**可选** `coverUri`（传了才渲染封面位，不影响曲库/歌单等既有纯文字列表），首页榜单传入各平台远程封面（44dp、SM 圆角）
- **推荐歌曲**（猜你喜欢）：推荐行此前是序号 + 歌名 +（歌手 · 理由），无封面；现改为**封面 + 歌名 +（歌手 · 理由）+ 平台标签**（44dp、SM 圆角），并去掉序号（封面已承担行首的视觉锚点）
- 顺带补上数据层的封面缺口（此前三个来源返回 null，UI 只能落占位）：
  - **QQ（搜索 + 榜单）**：两个接口都不直接给封面 URL，改用专辑 `mid` 拼 `y.gtimg.cn` 标准格式（实测 10/10 成功）
  - **酷狗搜索**：实测 `AlbumImage` 恒为空串，真正有值的是 `Image`（且带 `{size}` 占位符，需替换）
  - **网易搜索**：该接口只给加密 picId（转 URL 需 AES），保持留空由 UI 落占位；网易**榜单**有明文 picUrl，不受影响
- 联网冒烟测试（`ChartProviderSmokeTest`）新增封面断言：QQ 榜单 / QQ 搜索 / 酷狗搜索均 10/10

### 在线音源：沉浸页歌词不显示

- **根因**：封面/歌词此前只问洛雪脚本的 `pic` / `lyric` 动作，而**多数自定义源脚本只声明 `musicUrl`**（歌词与封面在洛雪桌面端由主程序自己的接口取，不归自定义源），所以绝大多数在线曲目必然没有歌词
- 现改为「脚本优先 → Muses 匹配系统兜底」：歌词走 AMLL → 平台五源 → LRCLIB（与刮削同一条链，`LyricsMatcher.matchDocument`），封面走 iTunes → kw → tx → wy → kg → mg；封面匹配链较慢，只在脚本与搜索结果都没图时才跑，不拖住歌词上屏
- 顺带修一个会让问题「永久化」的缺陷：元数据链（脚本歌词形态奇怪、解析异常）一旦抛错会**中断整条观察链**，之后切歌再也刷不出封面/歌词。播放页与迷你条均加异常兜底：单曲失败只清歌词、不中断订阅
- 补上此前缺失的验证：新增播放页 VM 层测试（在线·脚本无歌词 → 回退匹配上屏 / 在线·脚本有歌词 → 用脚本逐字 / 曲库曲目 → 曲库列），三条路径均绿

## 说明

- 手势前约 48px（touch slop，含内层）内抽屉不动，这是 Compose 手势的标准行为（Material3 抽屉同样如此）。曾尝试两条更"跟手"的路都已回退并留痕在代码注释：
  - `startDragImmediately = true`：位移不丢了，但会抢在内层之前 claim 手势——**首页横向胶囊直接滚不动**；
  - 自写 `pointerInput` 手势（想补偿 slop）：受 Compose「事件已被消费即取消拖拽」语义影响，实测 200px 滑只累积 **2.4px**。
- MuMu 实测：250px 慢滑可开、150px 慢滑回弹、榜单胶囊行横滑照旧滚动且不误开抽屉、抽屉展开时迷你条位置不变。
