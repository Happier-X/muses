# v0.6.7

## 变更

### 歌曲页「跳转当前曲」悬浮钮下移（修「太高」）

- 报障：歌曲页右下角回到当前歌曲的悬浮按钮位置**太高**，离底部 chrome 一大截
- 根因（`feature/library/.../SongsPage.kt` 的 `floatingActionButton` 槽）：FAB 抬升量是硬编码
  `192dp（窄屏）/ 104dp（宽屏）`，按 v0.6.0 时「迷你条 80dp + 胶囊底栏 88dp」的旧 chrome 尺寸推的；
  后来两件套都收窄到 56dp（`BottomChrome.kt` 口径：窄屏净高 128dp / 宽屏 80dp），
  窄屏实际 chrome 比 192dp 矮了约 40dp，FAB 就悬在了半空
- 处理：删掉 `BoxWithConstraints + 768dp 断点` 的复刻判断，改与列表末项**同口径**——
  `LocalBottomChromePadding`（窄屏 128 / 宽屏 80 + 系统导航 inset + 8dp 保底，由壳层 TabsLayout 提供）
  + 16dp 呼吸；多选条可见时再叠 64dp（与 `contentPadding` 避让一致）
  - 附带收益：FAB 避让从此随 `BottomChrome` 常量联动，chrome 再改尺寸不用二次修
- 编译：`:feature:library:compileKotlinJvm` 通过

### 曲库页顶部 tab 收成紧凑居中（对齐 miuix 官方尺寸）

- 背景：v0.6.6 把曲库页 tab 从 `TabRow` 换成 `TabRowWithContour` 后，仍按整行 `fillMaxWidth`
  均分成三个大胶囊，观感与 HyperOS 的分段控件差别明显（miuix 源码里每个 tab 限宽 76~98dp，
  官方 demo 放页面级 tab 时用的是非 contour 的 `TabRow`，`TabRowWithContour` 多用于卡片内）
- 处理：`feature/library/src/commonMain/kotlin/com/muses/player/feature/library/LibraryScreen.kt`
  用一个限宽（252dp ≈ 3 × 76dp + 2 × 9dp 间距）的**外层 Box 收窄约束**再居中
  - 踩坑：`Modifier.width(...)` 不能直接传给 TabRow 的 `modifier` —— 组件内部是先
    `fillMaxWidth()` 再 `then(modifier)`，那样只会把内容往里挤、整条仍然撑满
- 实测（模拟器截图）：三个 tab 收成紧凑居中，选中项为白色圆角滑动块

### 沉浸页转场掉帧 + 「方卡片」

- 掉帧根因：转场进度（`shellProgress`）此前作为**参数**传进 `PlayerShellBox`，等于在组合期读取
  `State` → 进度每帧变化就**重组整棵沉浸页**（歌词 + 封面 + 模糊背景全在里面），380ms 内每帧一次
  - 修复：改成传 lambda（`progress: () -> Float`），只在 `offset {}` / `graphicsLayer {}` 的 lambda
    里读取 → 只让该绘制层失效重绘，不再触发组合
- 圆角：卡片圆角基数 12dp → **28dp**（= 迷你条胶囊半径 56dp / 2），到全屏收到 0；
  之前 12dp 在转场中期只剩几 dp，看着就是个方块（转场起止也不再是「直角弹出」）

### 沉浸页开合改成「等比浮入」（对齐椒盐音乐）

- 之前不自然的根因：卡片按「迷你条矩形 → 全屏矩形」**非等比**插值（scaleX / scaleY 分别算），
  而迷你条是宽扁矩形（约 972×168），于是转场中文字与封面被横向拉伸、竖向压缩
- 现在：整页**等比缩放**（scaleX == scaleY，0.92 → 1）+ **从屏幕下方浮入** + 圆角 **28dp → 0**
  - 以底部中心为原点，缩放时卡片底部不动、向上展开
  - 不再依赖迷你条矩形做形变起点（`miniBarBounds` 及其上报链路一并移除）
- 实测（模拟器把系统动画放慢 30× 抓帧）：卡片带明显大圆角从底部浮出，内容比例正常、不变形，
  卡片外是干净的主页面

### 沉浸页转场：改为「从迷你条位置生长」+ 除封面外内容渐隐（对齐椒盐音乐）

- 上一版的问题：起点在**屏幕外底部**（「等比浮入」），与迷你条之间没有任何几何联系，
  观感只是「一块卡片从下面冒出来」——用户报障「并没有从迷你播放条弹过渡到沉浸式播放页面」，
  且转场中期卡片是方形（圆角已修，但形态仍不对）
- 处理（`feature/shell/.../MusesApp.kt` + `feature/player/.../PlayerScreen.kt`）：
  1. 恢复**迷你条矩形上报**（`boundsInWindow`，融合态 `CompactPlayerDock` 与展开态各一实例都要报）；
     `PlayerShellBox` 起点由该矩形决定：
     - 缩放**只按宽度比** `miniBounds.width / fullWidth`（等比 → 内容永不变形），
       起点时卡片横向与迷你条等宽
     - 平移把卡片中心对齐到迷你条中心，`p = 1` 时位移归零即全屏
     - 用 `translationX/Y` 而非 `offset`：不进布局，避免每帧重新摆放内容
     - 拿不到矩形时（首帧）退化为原「底部浮入」兜底
  2. **除封面外的内容随进度渐隐**（`contentAlphaFor`：进度 < 0.45 完全不可见，
     之后按 `FastOutLinearInEasing` 浮现）：标题、歌词面板、进度条、控制按钮
     → 点开先看到「封面飞出来」，内容后半段才浮现；收起时相反
     - 封面本身仍走 share element（`PlayerArtworkSharedKey`），不受这个 alpha 影响
- 实测（模拟器系统动画放慢 10× 抓帧）：打开早期只有封面可见、卡片从迷你条位置生长；
  中期内容浮现；关闭时内容先隐、封面缩回迷你条位置——两向对称

### 修沉浸页「卡」（流光背景每帧全屏 blur 是主要开销）

- 定位过程（`dumpsys gfxinfo` 逐阶段拆解，非猜测）：
  - `Traversal`（组合/布局）= 0.04ms → 前几轮的「延迟读进度」修法有效，组合确实没在每帧重组
  - 瓶颈在渲染侧：`SyncQueued → SwapBuffers` 中位 15.75ms（UI 线程等 GPU）
  - 再按「沉浸页静止不动」做基线：中位 **25ms**、janky 帧 **90/92（97.8%）** —— 说明是**常态慢**，
    不是转场引入的
- 根因：`FlowLayers` 每帧对**全屏**做一次 `blur(64.dp)`。而它的输入是 25×25 的光栅网格色图，
  本就是低频色彩场，放大时 `FilterQuality.Medium` 的双线性插值已经是平滑渐变，
  这个全屏高斯模糊**纯属冗余**，每帧白烧一遍 GPU
- 处理（`feature/player/.../backdrop/FlowingLightBackdrop.kt`）：
  1. 去掉 `FlowLayers` 的全屏 `blur(64.dp)`
  2. 帧时钟降频到 **20fps**（`FlowFrameIntervalMillis = 50`）：流光只是「色彩缓慢呼吸」
     （游走周期 7/11/17/23s），20fps 与 60fps 肉眼无差别，但每帧要付网格色重算 +
     625 像素 Hermite 光栅化
  3. 每层各建自己的光栅位图（两层过渡时共用一张会互相覆写）
- 实测（同一台模拟器，沉浸页静止 6s）：

  | 指标 | 改前 | 改后 |
  |---|---|---|
  | 中位帧耗时 | 25ms | **7ms** |
  | 90 分位 | 31ms | 11ms |
  | janky 帧 | 90/92（97.8%） | **2/92（2.2%）** |

  转场（开关各 2 次往返）：janky 帧 **76/236（32.2%）→ 13/213（6.1%）**，中位 22ms → 18ms
- 视觉：改前/改后截图逐帧对比，背景流光观感一致，无马赛克/色块

### 真机（MuMu 模拟器，1080×1920 / 480dpi）复验

同一份 APK 在 MuMu 上复测，确认上面的性能修复不是单机侥幸：

| 场景 | MuMu 实测 |
|---|---|
| 沉浸页静止 6s | 中位 **7ms**，janky **1/92（1.09%）** |
| 转场 ×2 往返 | 中位 18ms，janky **12/219（5.48%）** |
| 转场逐阶段拆解 | Traversal 0.04ms / 绘制提交 0.75ms / 等 GPU 2.51ms / **整帧中位 10.12ms**（16.67ms 预算内） |

- 帧级复核（`screenrecord` 逐帧时间戳）：转场期间 **67% 的帧间隔落在 12–20ms（≈58fps）**，
  其余长间隔来自两次操作之间的静止期（无内容变化不产帧），不属掉帧
- 观感复核（系统动画放慢 10× 抓帧）：打开时卡片自迷你条位置生长、仅封面可见，
  关闭时内容先隐、封面缩回迷你条位置，与另一台模拟器表现一致
