# v0.6.8

## 修复

### 车机包包名回退 `com.miui.player`（撤销 v0.6.7 的 QQ 音乐包名）

- 决策：v0.6.7 把 `miui` flavor 的 `applicationId` 改成官方 QQ 音乐包名 `com.tencent.qqmusic`，
  前提是「CarWith 的媒体/歌词卡片按**包名白名单**下发」。本轮复核确认**该前提不成立**，回退
- 反证（反编译椒盐音乐 12.3.2，包名 `com.salt.music`，即 `参考/decompiled/`）：
  - 全库唯一的系统会话 metadata 写入点（伪装包 `androidx/media3/ٱ.java` 的 `updateMediaSession`，
    case 8）里**没有任何包名判断，也没有 CarWith 专属代码**
  - 椒盐能让 CarWith 显示歌词，靠的是把**当前歌词行写进标准 `android.media.metadata.TITLE`**
    （开关「车载蓝牙歌词」`car_bluetooth_lyrics`，或「通知栏歌词」`notification_bar_lyrics`；
    同时 `ARTIST` 变成「艺术家 - 歌名」）——任何包名都能做
  - 洛雪音乐是同一路子：其 fork 的 track-player `MetadataManager.updateTitles()` 就是改 title
- 结论：换包名拿不到任何车机能力，只换来「旧包本地数据不继承」和「与官方 QQ 音乐签名互斥」
- 改动：`app/build.gradle.kts` 的 `miui` flavor 改回 `com.miui.player`（注释同步记录回退原因）；
  `.github/workflows/release.yml` 发布说明的 `-mi.apk` 描述同步改回；
  `changelog/v0.6.7.md` 属已发布版本（tag 已存在）的历史记录，保持原文不动
- **兼容性**：`-mi.apk` 从 v0.6.7 的 `com.tencent.qqmusic` 换回 `com.miui.player`，又是一次换包——
  装过 v0.6.7 车机包的设备需重装，本地数据（设置/曲库库表）不继承；
  一直用主包 `com.muses.player` 的用户完全不受影响

## 新功能

### 会话歌词桥接入 vivo 智能车载（Jovi InCar）私有 key

- 从椒盐音乐 12.3.2 还原出 vivo 车机歌词协议（对应其「vivo 智能车载（Jovi InCar）歌词」开关，
  与 CarWith 走的是两套东西）：

  | key | 值 |
  | --- | --- |
  | `ucar.media.metadata.UCAR_TITLE` | 歌名 |
  | `ucar.media.metadata.UCAR_ARTIST` | 艺术家 |
  | `ucar.media.metadata.LYRICS_LINE` | 当前歌词行 |

- `SessionLyricsBridge.push()` 由单 key 泛化为 4 个 key（`android.media.metadata.LYRICS` 全文 +
  上述三个），幂等短路改为「4 个 key 与系统会话现状**全一致**才跳过」，`null` 表示移除对应 key；
  仍然一次反射回写、fail-soft 自禁用
- `PlaybackService` 通知歌词模式下随 100ms 轮询同步写入**原始歌名 / 原始艺术家 / 当前歌词行**
  （取切歌时的元数据快照，避免被歌词模式污染）；关歌词模式或切歌时一并清空；
  前奏/间奏无匹配行仍保持上一次歌词行，不闪回歌名
- 同时修正 v0.6.7 注释里的错误归因：`LYRICS` 字段注入并非椒盐/洛雪的做法，保留为 fail-soft 兜底，
  不影响播放与通知

## 逆向工具链（本地产物，不入库）

- `参考/decompiled/decrypt_strings.py`：纯 Python 复现椒盐的 R8 字符串加密
  （`j52.ތ(long)` + 3×8191 字符表 `j52.ՠ` + `ko3.ހ(long)`），已知明文对自校验 **2/2** 通过
  （`-54496427736339 → car_bluetooth_lyrics`、`-54689701264659 → vivo_joviincar_lyrics`）
- 踩坑记录：`ko3.ހ` 末段是 `(long)(short)(...) ^ (v4_2 << 5)`——`(long)` 只作用于前面的 short，
  异或结果**不再截断**；若整体当 short 截断，解出的字符串会出现周期为 3 的错字
- 完整 key 表、触发条件与类索引见 `参考/decompiled/ANALYSIS.md` 第 6 节
