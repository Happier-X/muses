# v0.6.6

## 修复

### 沉浸页转场不再把整块背景涌到卡片之外（#53 后续）

- 现象：打开 / 关闭沉浸页时，能明显看到播放页的整块背景铺在卡片外面，没有被限制在正在形变的
  圆角矩形里（期望是椒盐音乐那种「卡片连内容一起缩放」）
- 定位到的三处原实现问题：
  1. `sharedBounds` 没传 `enter` / `exit` → 用默认 `fadeIn()` / `fadeOut()`，等于在整条转场上又叠了
     一层「整个沉浸页淡入淡出」，把形变观感盖掉 → 现在显式传
     `EnterTransition.None` / `ExitTransition.None`
  2. 形变中的外壳没有裁剪 → 内部 `fillMaxSize` 背景（深色底 / 流光图）仍按全屏绘制并溢出矩形
     → 宿主 `Box` 加 `clipToBounds()`
  3. 封面用 `renderInOverlayDuringTransition = true` 独立画在 overlay 层，不随外壳裁剪 / 缩放
     → 去掉，回到跟随外壳绘制
- 新增 `ScaleToBoundsBox`（布局固定用全屏约束、绘制用 `scaleX` / `scaleY` 缩放，全屏基准取最外层
  `BoxWithConstraints` 的约束）：本版本 `ResizeMode` 的两种模式实测都不会把形变矩形尺寸给到内容
  （`scaleToBounds()` 无效果、`RemeasureToBounds` 只表现为裁剪），所以要拿到「整页缩放」得自己算
- 实测（MuMu，把系统动画放慢 30× 逐帧采样）：转场期间播放页背景不再溢出卡片，卡片外是干净的主页面
- ⚠️ 待办：转场中卡片内看到的仍是「沉浸页被裁到矩形的那一块」（通常是封面区），**不是整页缩小**。
  要做到椒盐那种效果，需要按转场 fraction 自己算形变矩形（迷你条 bounds 捕获 + lerp + graphicsLayer
  缩放 / 位移 / 圆角），而不是依赖 `sharedBounds` 的自动形变

## 变更

### 沉浸页开合转场保持跟随系统动画设置（#53 结论）

- 现象：真机上点迷你条打开 / 收起沉浸式播放页没有任何展开形变（一帧到位），模拟器（MuMu）上正常
- 根因（已定位并复现）：系统「动画程序时长缩放」（`animator_duration_scale`，开发者选项；
  部分 ROM 的省电模式、无障碍「移除动画」也会把它置 0）为 0 时，Compose 的
  `Transition` / `sharedBounds` 会把整条转场**瞬时完成**
  - 排查中先排除：`v0.6.5` 的 tag 即转场提交、release APK 的 `classes.dex` 含
    `muses-player-shell`（不是发版漏带代码）、release 包重签名装到模拟器上转场正常（与 R8 无关）
  - 复现：`settings put global animator_duration_scale 0` 后点迷你条 → 首帧即全屏；
    设回 1x / 10x 立刻恢复正常转场
- 曾评估「绕开系统缩放」的方案（`withFrameNanos` 逐帧驱动 + `seekTo`，实测缩放置 0 时确实能播出完整形变），
  **经权衡不采用**：
  - 尊重显式设置——无障碍「移除动画」是晕动症 / 前庭敏感人群的刚需，而 `sharedBounds` 恰好是
    「全屏大幅缩放 + 位移」，属于最容易引发不适的运动类型
  - 避免节奏割裂——系统关动画时其余动画全是瞬时，唯独这里 380ms，容易被感知成「只有这里卡了一下」
  - 省电场景可能更差——关动画常伴随低端机 / 降频，`RemeasureToBounds` 逐帧重排的开销并不能被系统设置省掉
  - 维护成本——手写帧驱动绕开 Compose 的动画语义（驱动协程取消、中断续接、终态收敛都要自己管），
    后续升级 Compose 更易踩坑
- 结论：本转场继续走 `SeekableTransitionState.animateTo`，跟随系统动画设置。真机上「没有动画」属
  系统设置行为，不是 bug（CMP 1.12 已移除 `LocalMotionDurationScale`，app 侧也无法用
  CompositionLocal 局部覆盖该值）
- 顺带清理：`playerCollapseProgress` 自 v0.6.5 删掉「转场圆角 + 深色遮盖」后已无任何消费者，移除
- 转场时长抽为常量 `PlayerTransitionDurationMillis`（380ms），与 `PlayerShellBoundsTransform` 单源
