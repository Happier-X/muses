# 刮削对照与验收

核对日期：2026-10-15。

本文记录参考 Tagger 后，Muses 本轮已完成的改进和验证边界。这里的“自动测试通过”不代表已经在真实音频、Android 存储授权或 WebDAV 服务上完成验收。

## 参考与落地范围

参考来源：[Tagger 项目说明](https://github.com/Ericwyn/tagger#readme)。Tagger 将候选查询、逐字段审核和安全写回分开，并提供失败重试与历史恢复。以下是 Muses 针对自身双端结构采用的做法，不表示两个项目的实现或能力完全相同。

| 参考方向 | Muses 本轮结果 |
| --- | --- |
| 先审核再保存 | 候选保留供人工选择，AI 只调整审核选择，实际保存仍由用户应用 |
| 展示字段来源 | 标题、歌手、专辑可分别选择候选来源，保留手动编辑 |
| 避免误认版本 | 显示标题、歌手及版本疑点，明确冲突的文本不默认勾选 |
| 来源相互隔离 | 同来源请求排队，区分网络、超时、解析与 HTTP 错误，已有成功候选仍可审核 |
| 失败重试 | 只补查失败来源，保留候选下标、已选字段与编辑；来源和关键词草稿不混入旧结果 |
| 手动查询 | AMLL 手动审核绕过负缓存，普通播放继续使用原缓存策略 |
| 保存反馈 | 文件核验后更新曲库；分别说明文件保存失败与曲库更新失败 |
| 本地保存冲突 | 保存开始记录长度、修改时间与内容摘要；替换前检查，原地覆盖回退也检查，检测到外部改动时停止保存 |
| WebDAV 保存冲突 | 上传前比对远端内容摘要，使用强 ETag 条件上传并回读核验；失败保留已处理的本地副本和补传任务 |
| 防止重复保存 | 单曲与批量入口在启动写回前进入写回态，写回期间不启动第二次保存 |
| 避免无效覆盖 | 空白候选不能通过全选清空信息；单曲没有实际变更时保留审核与原撤销记录 |
| 停止任务 | 停止匹配后，迟到的读取结果和异常不能覆盖当前页面；取消信号继续传播 |
| 部分失败与撤销 | 批量仅成功歌曲出队；撤销逐曲处理，失败项保留供重试，完整恢复后才计成功 |
| 撤销字段范围 | 新记录只恢复本次触及的字段，未写入文件的封面只恢复曲库展示地址；旧记录兼容整组恢复 |
| 中断后的撤销 | 区分写前快照与已确认保存；未确认记录保留并提示核对文件，不自动覆盖文件或曲库 |
| 封面数据检查 | 写标签前识别 JPEG、PNG、GIF、WebP、BMP 签名；无法识别的数据不写入音频。撤销下载失败保留文件、曲库与记录供重试 |
| 封面下载上限 | HTTP 封面流式读取，单张默认最多 20 MiB；声明超限提前拒绝，无长度或长度偏小时按实际读取量停止，并释放响应 |
| 写回并发上限 | 本地写回有界并行，封面获取、文件保存与曲库更新合计最多同时处理 2 首；WebDAV 维持串行 |
| 封面未写入提示 | 封面下载失败或超出上限而未内嵌时，单曲提示、批量结果行与汇总都说明「文字已保存、封面未写入」，不再只显示成功 |
| 跨重启恢复 | 撤销记录持久化后，刮削页记录上一次写回并显示「上次写回 N 首可恢复标签」；含未确认写入时提示先核对文件 |
| 停止写回 | 批量写回期间可停止；已确认保存的歌曲留在撤销记录中，未写入的歌曲仍留在队列，界面说明已保存数量 |
| 放弃记录 | 撤销记录已无法恢复时（例如歌曲已从曲库删除）可以忽略；忽略前二次确认，忽略后队列页不再提示该记录 |
| 本地封面读取 | 普通路径及标准文件 URI 在后台按块读取，单张同样最多 20 MiB；保留中文、空格、特殊字符和 Windows 盘符语义 |

## 实机验收顺序

使用可恢复的音频副本和专用测试目录逐项检查，观察文件实际标签与曲库展示是否一致。

| 场景 | 操作与预期 |
| --- | --- |
| 逐字段组合 | 标题手改、专辑选另一来源，只勾这两个字段；保存后其他字段保持原值 |
| 身份与版本疑点 | 查询另一位歌手或现场版本；能看到疑点，冲突文本不会自动勾选 |
| 来源重试 | 让一个来源失败，编辑已有候选后重试；编辑和选择保留，成功来源不重复查询 |
| 草稿与结果 | 修改来源或关键词但不重新搜索；现有结果仍表示原查询，重试使用原结果的查询条件 |
| 空白与空操作 | 候选缺少歌手或专辑时全选，不清空原值；只选择相同文本时提示无需保存 |
| 连续应用 | 连点应用，或写回期间尝试重搜、返回；同一操作只产生一次保存 |
| 本地存储 | 在桌面目录及 Android 已授权目录各保存一次，重新读取音频确认标签；无权限时保留审核供重试 |
| 本地外部修改 | 在处理临时副本期间用其他程序修改原文件；检测到冲突时提示重新读取，不覆盖外部内容、不更新曲库 |
| 网络封面 | 下载成功后核对内嵌封面；下载失败时不误标已内嵌，文本仍按现有策略保存 |
| WebDAV | 正常上传后重新下载核对标签；断网或上传失败时不误报完整成功 |
| WebDAV 版本冲突 | 下载后由另一设备修改远端音频；上传应停止，远端新内容和本地待上传副本均保留；没有强 ETag 时不强行覆盖 |
| 批量部分失败 | 一首可写、一首不可写；成功歌曲出队，失败歌曲保留原选择，重试不重复写成功歌曲 |
| 停止与迟到结果 | 停止匹配后立即继续审核或应用；旧请求返回不切回匹配页，也不显示过期错误 |
| 撤销部分失败 | 让一首恢复失败；其余歌曲继续恢复，失败项保留，条件恢复后仅重试剩余项 |
| 撤销字段隔离 | 本次只改标题，随后修改歌手、专辑、歌词或封面再撤销；只恢复标题，其他字段及来源标记保持后来的值 |
| 写回中断 | 写回期间取消或异常退出后检查撤销；仅处理已确认保存的记录，未确认项保留并提示先核对文件 |
| 旧封面失效 | 保存新封面后使旧地址失效或返回错误页，撤销应失败且保留当前文件、曲库和记录；恢复地址后重试成功 |
| 超大下载封面 | 服务端返回超过 20 MiB 的封面，或不声明长度但持续发送；及时停止读取，按现有策略保存文本并将封面标为待内嵌；撤销遇到超限旧封面时保留记录供重试 |
| 批量并发上限 | 一次选择多首本地歌曲保存；同时最多处理 2 首，慢速存储下界面仍可响应，保存失败的一首不影响其余歌曲完成 |
| 封面未写入提示 | 让封面地址失效或返回超大文件后保存；单曲提示与批量结果都说明封面未写入，文字信息正常保存，曲库封面标记为待内嵌 |
| 跨重启恢复 | 写回后重启应用并进入刮削页；顶部显示可恢复条数，点「恢复标签」能逐首恢复；有未确认写入时先提示核对文件 |
| 停止批量写回 | 批量保存进行中点击「停止写回」；界面回到候选页并说明已保存数量，队列条目保留，未写入歌曲的文件与曲库不变 |
| 审核期间歌曲变化 | 打开单曲审核后更新曲库标题或迁移歌曲路径，再确认保存；写入当前路径，撤销恢复本次保存前的最新旧值；歌曲已删除或读取失败时不写旧文件 |
| 跨页面同时保存 | 一页保存尚未完成时从另一页应用候选或恢复；后者提示等待，候选保留，完成后可手动重试；第一项取消后也能重新保存 |
| 撤销编号与旧入口 | 连续写回同一首歌后，通过旧结果页操作恢复或忽略，不应改动新记录及新标签；当前记录仍可恢复；升级后已有旧编号记录仍可恢复 |
| 放弃撤销记录 | 让记录中的歌曲从曲库删除后再打开刮削页；点「忽略」并确认，记录消失且不再提示可恢复 |
| 本地封面地址 | 使用含中文、空格及特殊字符的封面文件，普通路径与标准文件 URI 均可内嵌；文件超过 20 MiB 时不读取完整内容，文本照常保存，封面保留展示地址并标为待内嵌 |

## 仍有边界

- 尚未完成上述真实设备、存储目录和 WebDAV 场景的实机验收。
- 本地文件已增加保存过程中的乐观冲突检查，第 35 步已增加草稿恢复时的文件版本核对，第 37 步已把可读取本地文件的审核基准传到实际写入器。最后一次检查与实际替换或原地打开之间仍存在竞态窗口，不能宣称已具备本地跨进程条件替换保证。
- WebDAV 已有内容摘要检查、强 ETag 条件上传和回读验证；保护依赖服务器正确执行条件请求，没有可靠版本时保留本地文件供导出。此前将 WebDAV 条件上传标为未实现的记录已更正。
- 本地冲突检查会增加文件的顺序读取次数，摘要按块计算；大文件与慢速存储的保存耗时仍需实机观察。
- 待刮削队列、撤销记录和待上传音频副本可持久化，待上传任务可重启后手动补传；第 35 步已增加匹配与审核草稿恢复，但所有写回任务不会自动续跑。
- 第 38 步为可读取的本地文件新增主封面字节快照；只涵盖首张主封面，不保存其他图片帧、描述和图片类型等全部标签结构。旧记录仍可能只有地址；读取未知、损坏或缺失快照不能宣称可恢复原图。
- 封面格式检查依据文件签名，不等同于完整解码；带有正确签名但内部损坏的数据仍可能通过检查。未识别的图片格式会拒绝保存。
- 20 MiB 限额覆盖刮削 HTTP 下载及本地读取的单张封面，不是整个批量任务的总内存上限。读取缓冲、结果副本与并行任务仍会占用额外内存。
- 本地读取在每块之间检查取消；同步文件读取本身不能保证即时中断。不支持的文件 URI 返回不可用，未新增 Android 内容 URI 或网络共享 URI 的读取适配。
- 同一编排器同时仅允许一次写回、恢复或忽略记录，批量保存内部的本地歌曲最多两首并行，WebDAV 歌曲仍串行；不同编排器实例各自有独立保护与并发额度。
- 封面未写入提示只说明状态，不会自动重新下载封面；需要用户重新刮削封面。批量结果行对这类歌曲不显示重试按钮，因为文字信息已经保存。
- 结果页与队列页的快捷撤销仍只操作当前记录，旧入口不会操作后来产生的记录；第 38 步新增独立历史入口，可选择较早批次中的歌曲，预览后恢复。
- 停止写回不能中断已经开始的单首文件替换，只会让尚未开始的歌曲不再写入；停止瞬间正在保存的歌曲可能完成也可能回退，界面按写入状态如实报告。
- 忽略快捷撤销入口前会二次确认，且只清空当前记录；第 38 步新增的已归档历史版本独立保留，确认文案已说明两者区别。
- 新记录已限制撤销字段范围；没有字段范围的旧记录仍沿用整组恢复，不能据此认为旧记录也获得相同隔离保护。
- 新记录写入前标记为未确认，正常完成或取消收尾后记录确认结果；异常退出留下的未确认项不能直接撤销，也不会自动判断文件是否实际保存。旧记录缺少状态标记，仍按原兼容策略视为已确认。
- 跨页面互斥依赖共用同一个编排器实例：Android 的同一 Koin 容器、桌面的同一刮削依赖图内生效。多个独立实例、其他进程及外部程序的并发修改不受此互斥保护；恢复收尾仍保留完整快照比较。
- 写前重新读取的是当前曲库快照，不是对文件实际标签的完整重新扫描；本次明确确认的字段仍会按候选值保存，不会自动合并期间对同字段的修改。
- 公共写回流程的撤销记录有数量上限，不是无限历史版本库。
- 第 35、36 步已补充 MusicBrainz 和录音、发行候选分组；年份、流派、音轨号等写回字段尚未扩展。

## 第 37 步：本地审核基准贯穿写回（2026-10-16）

可直接读取的本地文件现在把开始查询时的内容摘要、长度、修改时间及规范路径保留到审核候选，并在点击应用时传给写回流程。编排器在创建撤销记录和获取封面前，核对当前曲库字段、文件位置、来源与文件版本；实际本地写入器建立保存快照时再次比对审核版本，后续仍执行暂存副本核验和提交前冲突检查。未实现审核版本检查的写入器收到基准后会拒绝，不能静默降级为普通保存。

Android 授权目录写回同步接入：核对读取到的临时原音频摘要，并在提交前再次核对物理文件版本。可读取本地路径若无法取得审核基准，禁止应用；文件稍后恢复可读也不能沿用未知基准。内容 URI 和 WebDAV 本轮仍沿用已有写回保护，尚未建立审核期间的版本核验，不能据此宣称它们获得相同保护。

发现审核冲突后，不写文件、不更新曲库、不移除队列；保留候选和手改值，清空勾选，显示重新搜索并审核的提示。重新搜索成功后，新候选与新基准一起提交；等待、失败或取消期间保存输入仍使用旧候选自己的基准。恢复过期草稿时保留原文件版本和原曲库基准，不把当前版本静默绑定到旧候选；本地文件必须重新搜索后审核。

前置检查拒绝时不触碰上次撤销记录。实际写入器才发现冲突，且整批均明确未写入时，通过完整快照条件替换恢复上一条撤销记录；不会覆盖期间其他实例写入的新记录。一般保存失败可能已触及文件，不归入这种恢复条件。已有保存过程中的取消、回读核验和恢复规则继续生效。

此保护仍是乐观检查：最后一次核对与文件替换、授权 URI 打开之间存在窗口，无法保证跨进程原子条件写入；曲库核对也不等于重新扫描文件实际标签。文件摘要会增加顺序读取开销，慢速存储与大文件仍需实机观察。

## 第 38 步：多版本标签历史与主封面字节快照（2026-10-16）

刮削队列页新增「标签历史」入口。历史按写回批次和歌曲展示，选择后先预览目标字段、当前值、历史值、歌词摘要和主封面状态，确认后才恢复。只恢复该记录原本修改的字段；未确认写入项不出现在可恢复历史中。旧快捷撤销入口仍只匹配当前记录，不会因为增加历史而让旧按钮误恢复其他版本。

新批次覆盖当前记录时，在同一个 DataStore 事务中归档旧记录的已确认条目；同批次确认、取消收尾和条件回退不重复归档。历史展示最多最近 20 个批次，归档文本另有 8 MiB 原始快照预算，超限时较早批次可能提前淘汰。单批次仍沿用最多 200 首的记录范围，不是无限历史库。

Android 和桌面生产写回均接入实际标签读取。能读取本地文件时，历史旧值来自文件标签，另保留曲库来源信息；读取失败的记录明确标为曲库快照，不宣称已核对实际文件。主封面分为三种状态：确认无图、取得内容摘要与字节、读取未知。读取异常、外链图或损坏图片不能当成无图。封面快照存于应用数据目录，按 SHA-256 去重，单张最多 20 MiB，总量最多 256 MiB；写入先同步临时文件并校验，再保存引用，读取时再次核验摘要。容量满或读取失败时标为快照不可用，不删除仍可能被历史引用的数据；本轮尚未增加孤立快照清理入口。

恢复已有主封面快照时直接使用保存的图片字节，展示地址改为应用内快照位置，不依赖旧网络地址；确认无图才执行清空。新记录若尝试过快照但结果未知，快捷撤销也停止恢复并保留记录，不会降级为地址下载或清空。只保留主封面字节，不承诺还原多张内嵌图片的全部结构。

历史恢复会再次核对预览时的曲库与文件版本，并在修改前保存当前实际标签及主封面，形成新的撤销版本。无法取得恢复前实际标签、必要主封面或可靠文件版本时停止。已经开始的单曲恢复写入、结果接收及记录确认在不可取消区间内收尾，避免页面关闭后丢失已保存状态。恢复失败保留原历史，已写文件但曲库更新失败仍保留新撤销状态供核对。

当前历史恢复要求可核对的本地文件版本；内容 URI 和 WebDAV 尚不支持此入口的版本核验与实际标签快照，界面保留预览并说明不可恢复。旧快照若涉及封面但没有可靠字节，也不能从历史入口完整恢复本次字段。现有 WebDAV 写回与最新撤销流程继续沿用原有保护。
